# 下方复飞框读法教程：如何从小表格读出航段、字段和证据

本文专门讲航图下方复飞细节框，也就是剖面图附近的小表格、复飞步骤格、detail strip。
人工标注时，下面框是最重要的精细证据来源。上方 `MISSED APPROACH:` 文字可以告诉你整句话，但下面框通常把复飞动作拆成了一个个小格，最适合对应 PR #28 最大 JSON 的航段字段。

一句话原则：下面框不是普通图例，而是“复飞步骤压缩表”。读它时要按格子、按顺序、按动作拆成航段，再把每个小元素挂到 Q1-Q5 字段。

---

## 1. 先判断哪里才是“下面复飞框”

下面复飞框通常出现在：

- 剖面图上方或右上方。
- 最低标准表上方。
- 跑道小图旁边。
- 下方 profile view 和机场图之间。

它常见外观：

- 一排或多排矩形小格。
- 格子中有高度数字、向上箭头、弯曲箭头、fix 名称、navaid、radial、inbound/outbound。
- 旁边可能有竖线，把每个步骤分开。

它不是：

- 最低标准表。
- FAF to MAP 时间表。
- 机场图。
- 普通下降剖面高度。
- MSA 圆。
- 跑道长度、TDZE、机场标高。

人工处理顺序：

1. 先找到下方复飞细节总框 `MISSED_APPROACH_DETAIL_AREA`。
2. 确认总框只覆盖复飞步骤小表格或主要 detail strip。
3. 再在总框内逐个读小格。
4. 最后把小格里的具体符号和文字拆成小框。

---

## 2. 下面框应该按什么顺序读

大多数情况下，下面框按复飞动作顺序排列。

常见读法：

- 从左到右读。
- 如果有上下两行，先读同一格里的上方值和下方说明，再读下一格。
- 竖线通常表示步骤边界。
- 一个格子不一定等于一个航段，但通常对应一个航段的核心证据。
- 一个航段可能跨多个小框，例如 `COE`、`R-350`、`outbnd` 三个小框共同描述同一个 radial 航段。

读下面框时先问四个问题：

1. 这一格有没有高度？如果有，通常对应 `Q2_altitude_constraint`。
2. 这一格有没有箭头或弧线？如果有，通常对应 climb 或 turn，即 `Q3_turn`，有时也帮助判断航段类型。
3. 这一格有没有 fix/navaid 名称？如果有，通常对应 `Q1_fix_ident` 或 `Q4_course_or_radial` 的 navaid 部分。
4. 这一格有没有 heading/radial/track/inbound/outbound/DME/hold？如果有，对应 `Q4_course_or_radial` 或 `Q5_hold_params`。

不要只看一个数字或一个符号，要把同一格和相邻格结合起来读。

## 3. 下面框里的常见符号怎么读

### 3.1 高度数字

例子：

- `3000`
- `4000`
- `7000`
- `8700`
- `11000`
- `6500`
- `500`

含义：

- 通常表示复飞过程中的爬升高度或高度限制。
- 对应 PR #28 的 `Q2_altitude_constraint`。

怎么框：

- 用 `ALTITUDE_TEXT`。
- 只框高度数字本身。
- 不要把箭头、fix 名称、radial 一起框进去。

怎么对应：

- 看该高度属于哪个步骤或航段。
- 如果高度在第一格，通常对应第一个 climb 航段。
- 如果后面还有另一个高度，可能对应后续航段。

容易错的地方：

- 不要把普通进近剖面高度当复飞高度。
- 不要把最低标准表里的数字当复飞高度。
- 不要把机场标高、TDZE、跑道长度当复飞高度。

### 3.2 向上箭头

含义：

- 表示 climb。
- 常和高度数字一起出现。
- 它说明动作是爬升，但具体高度通常由旁边高度数字提供。

怎么框：

- 用 `CLIMB_ARROW`。
- 只框箭头主体。
- 不要把高度数字一起框进同一个小框，除非图太紧密实在分不开。

怎么对应：

- 箭头本身通常不直接给高度值。
- 它可以支持 `CA`、`VI` 等爬升相关航段，或作为 `Q3_turn`/动作证据。
- 高度字段仍应由 `ALTITUDE_TEXT` 确认。

### 3.3 弯曲箭头 / 转弯弧线

含义：

- 表示 turn。
- 弧线向左或向右，说明转弯方向。
- 常对应 `Q3_turn`。

怎么框：

- 用 `PATH_SEGMENT` 或 `HOLDING_ARC`。
- 如果只是普通转弯，用 `PATH_SEGMENT`。
- 如果明确是等待图形的一部分，用 `HOLDING_ARC` 或 `HOLDING_PATTERN`。

怎么对应：

- 如果候选字段是 `Q3_turn = LEFT`，你要确认弧线确实是左转。
- 如果候选字段是 `Q3_turn = RIGHT`，你要确认弧线确实是右转。

容易错的地方：

- 不要把普通进近路径弯曲当复飞转弯。
- 不要把跑道图上的线当复飞转弯。
- 如果弧线方向看不清，标不确定。

### 3.4 fix 名称

例子：

- `MUDRE`
- `ZEXEL`
- `SWOBS`
- `TELLE`
- `EVVIS`
- `CELTS`
- `BURDE INT`
- `CONNI AHN`

含义：

- 复飞要飞向、经过或等待的定位点。
- 对应 `Q1_fix_ident`。

怎么框：

- 用 `FIX_TEXT`。
- 框住 fix 名称本身，例如 `MUDRE`、`BURDE`。
- `INT` 可以和 fix 名称一起框，也可以不框，关键是 fix 名称必须清楚。

怎么对应：

- 如果候选显示 `Q1_fix_ident = MUDRE`，当前框必须能看到 `MUDRE`。
- 如果候选显示 `Q1_fix_ident = BURDE`，框只框到 `INT` 不够，必须包含 `BURDE`。

容易错的地方：

- 不要把 navaid/radial 当 fix。
- 不要把进近段 fix 当复飞目标 fix。
- 同一个 fix 在平面图和下面框都出现时，优先用下面框里更直接的证据。

### 3.5 fix 符号

含义：

- 图形形式的 fix/navaid 位置。
- 常见为菱形、四角星、三角形、VOR/NAVAID 符号。

怎么框：

- 用 `FIX_SYMBOL`。
- 只框符号，不要框一大片空白。

怎么对应：

- 它通常作为 `Q1_fix_ident` 的辅助证据。
- 如果旁边有 fix 名称，最好同时保留文字框。

注意：

- 文字比符号更容易直接对应字段。
- 只有符号没有文字时，要看周围标注确认它是不是目标 fix。

### 3.6 navaid 名称

例子：

- `STW`
- `COE`
- `SGD`
- `BOS`
- `AHN`
- `ALS`

含义：

- 导航台名称。
- 可能是航段目标，也可能是 radial 的 navaid 部分。

怎么框：

- 用 `NAVAID_TEXT`。
- 只框 navaid 名称。

怎么对应：

- 如果它是目标点，可支持 `Q1_fix_ident`。
- 如果它和 `R-xxx` 一起出现，例如 `STW R-243`，通常支持 `Q4_course_or_radial`。

容易错的地方：

- `COE` 在 `COE R-350` 中不是高度，也不是普通文字，它是 radial 的导航台部分。
- `SGD R-230` 中，`SGD` 和 `R-230` 最好分开框。

### 3.7 radial：`R-xxx`

例子：

- `R-243`
- `R-350`
- `R-154`
- `R-230`
- `R-235`

含义：

- 径向线。
- 通常对应 `Q4_course_or_radial`。

怎么框：

- 用 `RADIAL_TEXT`。
- 只框 `R-xxx`。

怎么对应：

- 通常要和 navaid 名称一起理解。
- `STW R-243` 应理解为 STW 的 243 radial。
- `COE R-350 outbnd` 应理解为 COE 的 350 radial outbound。

容易错的地方：

- 不要把 `R-243` 挂成 `Q1_fix_ident`。
- 不要把航图上普通进近 radial 当复飞 radial。

### 3.8 heading / track / course

例子：

- `hdg 063°`
- `heading 100°`
- `tr 284°`
- `063°`
- `294°`

含义：

- heading、track、course、航迹方向。
- 通常对应 `Q4_course_or_radial`。

怎么框：

- `hdg 063°` 用 `HEADING_TEXT`。
- `tr 284°` 用 `TRACK_OR_RADIAL_TEXT`。
- 只有角度但上下文明确是航向，也可以用 `HEADING_TEXT` 或 `TRACK_OR_RADIAL_TEXT`。

怎么对应：

- 航图常显示整数，424 可能显示小数。
- 例如 424 是 `63.3°`，航图显示 `063°`，通常可以对应。
- 例如 424 是 `294.4°`，航图显示 `294°`，通常可以对应。

容易错的地方：

- 不要去图上强行找 424 的小数。
- 不要把 `APP CRS` 或 final approach course 当成复飞 heading。

### 3.9 inbound / outbound

例子：

- `inbnd`
- `outbnd`
- `inbound`
- `outbound`

含义：

- 描述沿某 radial 的方向。
- 通常是 `Q4_course_or_radial` 的组成部分。

怎么框：

- 用 `OUTBOUND_INBOUND_MARK`。
- 只框这个方向词。

怎么对应：

- 与 navaid 和 radial 一起确认。
- 例如 `COE R-350 outbnd` 需要共同理解为 `COE` + `R-350` + `outbound`。

容易错的地方：

- 不要把 `outbnd` 单独当 fix。
- 不要漏掉方向词，因为 inbound/outbound 会改变含义。

### 3.10 holding 图形、时间、距离

常见证据：

- holding racetrack。
- holding arc。
- `1 min`。
- `One Minute Holding Pattern`。
- `4 NM`、`5 NM`。
- `20.5 DME`、`30.2 DME`。

对应字段：

- `Q5_hold_params`

怎么框：

- holding 图形用 `HOLDING_PATTERN` 或 `HOLDING_ARC`。
- 时间用 `HOLDING_TIME_TEXT`。
- 距离或 DME 用 `DME_DISTANCE_TEXT`。
- holding fix 名称仍用 `FIX_TEXT`。

容易错的地方：

- FAF 到 MAP 距离不是 holding 距离。
- MSA 圆里的数字不是 holding 参数。
- 只有普通弧线不一定是 holding，要看是否有 hold/racetrack/holding fix。

## 4. 怎么把下面框拆成航段

### 4.1 用格子边界拆

如果下面框有竖线：

- 每个竖线隔开的区域通常是一段动作。
- 一个格子里可能有高度 + 箭头，说明 climb to altitude。
- 下一格可能有转弯弧线，说明 turn。
- 再下一格可能有 fix/radial，说明 fly to fix 或 intercept radial。

但不要机械认为“一个格子等于一个航段”。有时一个航段的信息分散在相邻几个小格里。

### 4.2 用动作顺序拆

按复飞指令顺序：

1. climb / climb to altitude。
2. turn left/right 或 continue climbing。
3. fly direct / intercept / proceed on radial。
4. reach fix。
5. hold。

下面框通常把这些动作压缩成图形和文字。

### 4.3 用候选航段类型辅助判断

如果右侧候选显示：

- `CA`：重点找高度和爬升箭头。
- `VI`：重点找 heading/course/turn/intercept。
- `CF` 或 `DF`：重点找目标 fix。
- `HM`：重点找 holding 图形和 holding 参数。

但是注意：候选来自 424，不是图上自动证明。人工仍要看图上是否有证据。

## 5. 常见下面框例子怎么读

### 5.1 例子：`3000` + 向上箭头 + `hdg 063°` + `STW R-243` + `MUDRE INT`

读法：

1. `3000`：爬升高度，对应 `Q2_altitude_constraint`。
2. 向上箭头：climb 动作，对应爬升证据。
3. `hdg 063°`：heading，对应 `Q4_course_or_radial`。
4. `STW`：navaid，对应 radial 的 navaid 部分。
5. `R-243`：radial，对应 `Q4_course_or_radial`。
6. `MUDRE INT`：目标 fix，对应 `Q1_fix_ident`。

标注方式：

- `3000` 单独 `ALTITUDE_TEXT`。
- 向上箭头单独 `CLIMB_ARROW`。
- `hdg 063°` 单独 `HEADING_TEXT`。
- `STW` 单独 `NAVAID_TEXT`。
- `R-243` 单独 `RADIAL_TEXT`。
- `MUDRE` 或 `MUDRE INT` 单独 `FIX_TEXT`。

### 5.2 例子：`8700` + `11000` + 弯曲箭头 + `ALS` + fix 符号

读法：

1. `8700`：先爬升到某高度。
2. 弯曲箭头：转弯。
3. `11000`：继续爬升到更高高度。
4. `ALS`：导航台或 fix。
5. fix 符号：辅助定位证据。

注意：

- `8700` 和 `11000` 可能属于不同阶段，不要随便挂到同一航段。
- 弯曲箭头用于转弯方向，不是高度。
- `ALS` 如果是目标点，挂 `Q1_fix_ident`；如果是 radial/navaid 组成，挂 `Q4_course_or_radial` 的相关证据。

### 5.3 例子：`500` + `3200` + 弯曲箭头 + `SGD` + `R-230` + `BURDE INT`

读法：

1. `500`：初始爬升高度。
2. `3200`：后续爬升高度。
3. 弯曲箭头：转弯。
4. `SGD`：navaid。
5. `R-230`：radial。
6. `BURDE INT`：目标 fix。

常见错误：

- 漏框 `BURDE INT`。
- 只框 `SGD`，漏框 `R-230`。
- 把 `SGD R-230` 整体框太大，导致不清楚哪个字段对应哪个值。

正确处理：

- `SGD` 用 `NAVAID_TEXT`。
- `R-230` 用 `RADIAL_TEXT`。
- `BURDE INT` 用 `FIX_TEXT`。
- 高度分别框。

### 5.4 例子：`4000` + 向上箭头 + `AHN R-235` + `CONNI AHN 30.2`

读法：

1. `4000`：复飞高度。
2. 向上箭头：climb。
3. `AHN`：navaid。
4. `R-235`：radial。
5. `CONNI`：fix。
6. `AHN 30.2`：DME 或距离条件。

常见错误：

- 只框 `CONNI`，漏掉 `AHN 30.2`。
- `4000` 框偏到边线外。
- `R-235` 被挂到 fix 字段。

### 5.5 例子：`3000` + `BOS R-154` + `CELTS` + 三角符号

读法：

1. `3000`：高度。
2. `BOS`：navaid。
3. `R-154`：radial。
4. `CELTS`：fix。
5. 三角符号：fix 符号证据。

标注方式：

- `3000` 用 `ALTITUDE_TEXT`。
- `BOS` 用 `NAVAID_TEXT`。
- `R-154` 用 `RADIAL_TEXT`。
- `CELTS` 用 `FIX_TEXT`。
- 三角符号用 `FIX_SYMBOL`。

### 5.6 例子：`2900` + `6000` + `COE R-350 outbnd` + `6500` + `COE R-350 inbnd` + `COE`

读法：

这是多航段复飞，不能当成一个航段。

可能顺序：

1. 爬升到 `2900`。
2. 左转或继续爬升到 `6000`。
3. 沿 `COE R-350 outbound`。
4. 再爬升到 `6500`。
5. 沿 `COE R-350 inbound`。
6. 到 `COE` 并 hold。

标注方式：

- `2900`、`6000`、`6500` 分别框。
- 两个 `COE` 如果出现在不同格，应分别按所在航段确认。
- 两个 `R-350` 如果分别对应 outbound/inbound，不要混成一个。
- `outbnd` 和 `inbnd` 必须分别框。

常见错误：

- 把所有 `COE R-350` 只挂到一个字段。
- 漏掉 `outbnd` 或 `inbnd`。
- 把 `6500` 误挂到第一段。

## 6. 下面框与 PR #28 字段的对应口诀

| 看到什么 | 优先想到哪个字段 | 用什么框 |
|---|---|---|
| 高度数字 | `Q2_altitude_constraint` | `ALTITUDE_TEXT` |
| 向上箭头 | climb 动作 / 航段动作证据 | `CLIMB_ARROW` |
| 左右弯曲箭头 | `Q3_turn` | `PATH_SEGMENT` |
| fix 名称 | `Q1_fix_ident` | `FIX_TEXT` |
| fix 图标 | `Q1_fix_ident` 辅助 | `FIX_SYMBOL` |
| navaid 名称 | `Q1_fix_ident` 或 `Q4_course_or_radial` | `NAVAID_TEXT` |
| `R-xxx` | `Q4_course_or_radial` | `RADIAL_TEXT` |
| `hdg xxx°` | `Q4_course_or_radial` | `HEADING_TEXT` |
| `tr xxx°` | `Q4_course_or_radial` | `TRACK_OR_RADIAL_TEXT` |
| inbound/outbound | `Q4_course_or_radial` | `OUTBOUND_INBOUND_MARK` |
| holding racetrack | `Q5_hold_params` | `HOLDING_PATTERN` |

## 7. 下面框读错时怎么处理

### 7.1 值看到了，但航段不确定

处理：

1. 看上方 `MISSED APPROACH:` 原文。
2. 看下面框的左右顺序。
3. 看右侧候选航段类型。
4. 仍不确定就点“不确定”，备注“航段顺序不确定”。

不要只因为值一样就随便确认。

### 7.2 框已经挂到字段，但发现挂错

处理：

1. 在候选字段里点“取消挂接”。
2. 或在字段对应里点“不属于此框”。
3. 选择正确框重新挂。

### 7.3 下面框缺了一个小元素

处理：

1. 选正确类型。
2. 点“框选新增”。
3. 贴紧该小元素画框。
4. 挂到对应字段。

常见要补：

- `BURDE INT` 漏框。
- `4000` 漏框。
- 转弯箭头漏框。
- `tr` 或 `inbnd/outbnd` 漏框。
- 第二个 `COE` 或第二个 `R-350` 漏框。

### 7.4 下面框多框或重框

处理：

- 保留最准确的框。
- 重复框不要都确认。
- 错误框可以删除或标不属于此框。

### 7.5 下面框被总框框住了，但没有小框

处理：

- 总框只是定位。
- 仍需要给高度、箭头、fix、radial 等加小框。
- 不要只确认总框就保存。

---

## 8. 最后检查：读下面框是否合格

保存前问自己：

1. 下面复飞细节总框是否框对区域？
2. 每个高度是否单独框了？
3. 每个箭头/弧线是否单独框了？
4. 每个 fix/navaid 名称是否单独框了？
5. 每个 `R-xxx` 是否单独框了？
6. inbound/outbound 是否没有漏？
7. holding 图形、时间、距离是否只在真正 holding 时确认？
8. 每个 confirmed 字段是否都能说清航段编号和字段名？
9. 有没有把普通进近剖面内容误当复飞？
10. 有没有为了消 missing 而硬确认不确定内容？

如果以上都能回答清楚，下面框就读得比较可靠。

---

## 9. 一句话总结

读下面框时，不要把它看成一张小图；要把它看成“复飞航段表”。
高度归 Q2，fix 归 Q1，转弯归 Q3，航向/径向归 Q4，holding 归 Q5。
先按格子和顺序拆航段，再按字段挂证据，不确定就备注，不要硬确认。
