# 字段证据来源标注流程 v2

本文档记录普通参与者界面的重构方案。新的主流程以字段为单位，但标注目标不是抽象判断字段对错，而是确认每个字段的证据来源：哪些已框出的航图元素支持该字段，以及这种支持关系属于哪一类。

## 设计目标

1. 普通参与者只处理当前字段，不同时暴露完整 JSON、全部候选映射和开发检查信息。
2. 系统自动把候选证据框放进当前字段的证据篮子，参与者优先做核对和小修正。
3. 添加、删除、调整证据框不等于完成字段；只有点击“确认本字段并继续”才记录字段结论并进入下一个字段。
4. “多证据综合”和“规则/默认补全”都必须绑定证据框。按钮表达的是当前证据篮子的支持类型，不是脱离证据的抽象标签。
5. “缺少足够编码信息”是正向结论，用于专家确认已检查相关航图来源后，仍不能从航图恢复该 JSON 字段。

## 主流程

1. 左侧选择航图。
2. 正式集先领取；领取后发现难度超出能力范围，可退回专家复审。
3. 右侧进入“当前字段”：
   - 系统显示一个字段目标：航段、字段名、目标值。
   - 系统自动填入候选支持框，形成当前字段的证据篮子。
   - 中间航图高亮证据篮子里的框；选中的框另有更强高亮和标签。
4. 参与者核对证据篮子：
   - 选中图上的现有框，点击“加入/移除选中框”。
   - 候选框不准时，拖动边界微调。
   - 缺少框时，点击“画新支持框”，新框自动加入当前字段证据篮子。
   - 错框可以删除，但删除是框级操作，不是字段结论。
5. 参与者选择字段来源类型并确认：
   - 直接图面证据：当前证据框可以直接读出该字段。
   - 多证据综合：当前证据框共同构成一个可见事实，缺一不可。
   - 规则/默认补全：当前证据框只是前提，还需要航图省略、程序规则或默认语义补全。
   - 缺少足够编码信息：已检查相关来源，航图不足以恢复该字段。
   - 不确定：普通参与者不能稳定判断，交给复核。
6. 系统记录字段结论并跳到下一个待审字段。
7. 所有 present 字段处理完成后，点击“完成本图”。

## 数据结构

每个字段保存一条 `field_review_v2` 记录：

```json
{
  "schema": "field_review_v2",
  "field_key": "leg1.Q2_altitude_constraint",
  "chart_id": "...",
  "candidate_leg_id": "...",
  "canonical_leg_index": 1,
  "leg_type": "CA",
  "field_name": "Q2_altitude_constraint",
  "canonical_answer": {"status": "present", "value": "..."},
  "review_status": "visible_joint",
  "support_mode": "visible_joint",
  "required_evidence_region_ids": ["R1", "R2"],
  "secondary_evidence_region_ids": [],
  "evidence_region_ids": ["R1", "R2"],
  "evidence_source": ["ma_text", "plan_view"],
  "checked_scopes": ["ma_text", "plan_view"],
  "notes": "",
  "reviewed_by": "P001",
  "reviewed_at": "..."
}
```

`support_mode` 是字段来源类型：

- `pending`：尚未确认。
- `direct_visible`：直接图面证据。
- `visible_joint`：多证据综合，所列 `required_evidence_region_ids` 缺一不可。
- `rule_default_completion`：规则/默认补全，所列框是推导前提。
- `insufficient_for_encoding`：缺少足够编码信息。
- `uncertain`：不确定，进入复核。
- `not_applicable`：非 present 字段或无需人工处理。

为了兼容现有导出和旧草稿，`review_status` 与 `support_mode` 保持同值；`evidence_region_ids` 是主证据和辅助证据的合并视图。

## 界面分工

- 左侧“任务队列 / 本图操作”：只负责选择、领取、暂存、退回、完成。
- 中间航图：只负责看图、选框、微调框和画新框。
- 右侧“当前字段”：唯一主工作区，包含字段目标、证据篮子、来源类型确认和待审字段列表。
- “已选证据框”：查看当前框的含义和高级属性；普通流程通常不需要展开高级框信息。
- “选中框支持的字段”“批量与候选工具”“全部候选字段”“开发检查”都属于高级辅助区，不是普通参与者的主流程。

## 保存语义

- 加入证据框、画新框、调整框，只保存为当前字段的未完成草稿。
- 点击来源类型确认按钮，才将字段从 `pending` 变为已完成状态。
- 暂存会保存 pending 草稿；完成本图要求没有 pending 字段。
- `rule_default_completion` 和 `visible_joint` 都必须携带证据框；没有证据框时只能选择 `insufficient_for_encoding` 或 `uncertain`。
