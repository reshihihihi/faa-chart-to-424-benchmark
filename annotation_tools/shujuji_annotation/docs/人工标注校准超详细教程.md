# FAA 复飞航图人工标注校准超详细教程

本文用于 `tools/shujuji_annotation` 正式 300 张 FAA missed approach 航图的多人协同人工校准。

最新版按“操作步骤、框类型、字段对应、异常处理”展开的培训手册见：

`docs\正式标注操作手册_步骤与字段对应.md`

核心原则：人工不是重新录入一份 JSON，而是确认“航图上的框”能否作为证据，支持 CIFP/424 转换出的 PR #28 最大集合 JSON 中某个航段、某个字段。

如果人工确认正确，并且所有需要图上证据的 `present` 字段都确认完整，系统生成的 `annotation_pr28_json` 就可以和 424 转换来的 `canonical_proxy_gt` JSON 严格一致。

---

## 1. 人工到底需要确认什么

人工需要确认 5 类正确性。

### 1.1 确认自己领取的是正确航图

你需要确认：

- 左栏显示的 `chart_id` 是你准备标的图。
- 正式标注前已经填写自己的标注人编号或姓名。
- 左栏该航图已经被你点击“领取”。
- 这张图没有显示“已被别人领取”。

为什么要这样做：

- 多人协同标注时，领取记录会写入 `claims.json`。
- 每个人只标自己领取的图，避免两个人重复标同一张图。
- 保存时系统会检查当前图是否由当前标注人领取，没有领取不能保存正式结果。

操作：

1. 打开正式网页。
2. 右上角填写“标注人”，建议使用固定编号，例如 `A01`、`A02`、`LXL`。
3. 在左栏找到一张显示“未领取”的航图。
4. 点击该航图卡片里的“领取”按钮。
5. 左栏状态变为“我已领取”后，再开始检查和保存。

不要这样做：

- 不要不填标注人就开始。
- 不要标别人已经领取的图。
- 不要多人共用同一个标注人名字。
- 不要只打开图不领取就保存，系统会阻止正式保存。

---

### 1.2 确认大框是否正确

网页中通常有三个大框。

#### A. 上方复飞文字大框：`MISSED_APPROACH_TEXT`

它应该框住航图上方的 `MISSED APPROACH:` 文字说明。

你需要确认：

- 框住了完整的复飞文字说明。
- 没有漏掉关键内容，例如 altitude、turn、direct、fix、hold、DME、radial 等。
- 框可以稍微大一点，覆盖完整文字即可。
- 不需要把上方文字拆成很多小框。

可以接受：

- 大框包含一点相邻空白。
- 大框包含标题 `MISSED APPROACH:` 和后面的完整句子。

不能接受：

- 只框住标题，没有框住后面的指令。
- 漏掉第二行或第三行复飞说明。
- 框到完全无关的频率栏、跑道信息栏，导致证据不清楚。

#### B. 平面图复飞相关区域大框：`PLAN_VIEW`

它应该框住平面图中复飞相关上下文。

你需要确认：

- 覆盖复飞路径、复飞 fix、navaid、radial、holding、转弯方向等相关内容。
- 不要求非常精细，可以作为上下文大区域。
- 如果图上有 `MISSED APCH FIX` 小插图，也应尽量包含在相关大区域或另有框覆盖。

可以接受：

- 大框覆盖整个平面图主体。
- 大框包含一些非复飞信息，因为它是上下文框。

不能接受：

- 平面图大框完全没有覆盖复飞路径。
- 关键复飞 fix 或 holding 小插图在框外。

#### C. 下方复飞细节总框：`MISSED_APPROACH_DETAIL_AREA`

它应该框住下方剖面图附近的复飞小表格或复飞 detail strip。

你需要确认：

- 总框框住的是下方复飞小表格、复飞步骤框或复飞 detail 区域。
- 这个总框里面通常会有高度、箭头、fix、radial、course、holding arc 等小元素。
- 总框只是定位用，里面的元素仍需要小框逐个确认。

可以接受：

- 总框比小表格稍大，包含一点空白。
- 总框包含完整复飞步骤区域。

不能接受：

- 总框跑到普通 profile 剖面高度、普通下降航迹、最低标准表格。
- 总框只框住一半复飞小表格。
- 总框把真正的复飞小表格漏在外面。

### 1.3 确认小框是否正确

小框是重点。小框必须尽量贴住单个复飞相关符号或文字。

小框不是为了好看，而是为了回答：这个图上证据能不能支持某个航段的某个 PR #28 字段。

#### `ALTITUDE_TEXT` 高度文字

应该框：

- `3000`
- `7000`
- `500`
- `8700`
- `11000`
- `6000`
- `2600`
- 类似的复飞高度限制文字

判断标准：

- 框中应主要是一个高度数字。
- 如果一个高度属于复飞小表格，应框它。
- 如果同样的数字出现在普通进近 profile，不一定属于复飞字段，要看是否在复飞小表格或复飞路径里。

不能框：

- 最低标准表里的 MDA、DA、visibility。
- 跑道长度、TDZE、机场标高，除非它明确属于复飞指令。
- 普通进近下降高度，除非它是复飞字段证据。

#### `CLIMB_ARROW` 爬升箭头

应该框：

- 复飞小表格中的向上箭头。
- 表示 climb 的竖直箭头。

判断标准：

- 箭头应与复飞高度或 climb 指令相邻。
- 它通常支持 `CA`、`VI` 等爬升/航向类航段。

不能框：

- 普通航迹方向箭头。
- 跑道图、机场图里的方向箭头。
- 不属于复飞步骤的箭头。

#### `FIX_TEXT` 定位点文字

应该框：

- `MUDRE`
- `ZEXEL`
- `SWOBS`
- `TELLE`
- `EVVIS`
- `ONICE`
- 其他复飞 fix 名称

判断标准：

- 文字对应 CIFP/424 中某个航段的 `Q1_fix_ident`。
- 如果小表格里有 fix 名称，应框文字。
- 如果 fix 也在平面图中出现，可以优先框复飞小表格里的文字；必要时也可框平面图里的证据。

不能框：

- 进近段 fix，除非它确实是复飞航段目标。
- 机场名、城市名、标题。

#### `FIX_SYMBOL`

应该框：

- 四角星/菱形 fix 符号。
- VOR/NAVAID 相关符号。
- holding fix 位置符号。

判断标准：

- 符号应和对应 fix 名称或复飞步骤相邻。
- 如果 `FIX_TEXT` 已经框了文字，`FIX_SYMBOL` 可以作为额外证据。

不能框：

- MSA 圆里的符号，除非它就是复飞 fix 证据。
- 跑道机场图里的无关符号。

#### `NAVAID_TEXT`

应该框：

- `STW`
- `COE`
- `BOS`
- `SGD`
- `AHN`
- 其他导航台标识。

判断标准：

- 它通常支持 `Q4_course_or_radial` 中的 `navaid_radial`。
- 例如 `STW R-243` 中，`STW` 应作为 navaid。

不能框：

- 频率里的 navaid 信息，除非复飞字段明确依赖它。
- 与复飞路径无关的导航台。

#### `RADIAL_TEXT`

应该框：

- `R-243`
- `R-350`
- `R-154`
- `R-230`
- 其他 radial 字段。

判断标准：

- `R-xxx` 通常对应 PR #28 的 `Q4_course_or_radial`。
- 如果航图写的是 `COE R-350 inbound`，要分别框 `COE`、`R-350`、`inbound`。

不能框：

- 普通进近航迹上的 radial，除非它属于复飞航段。

#### `HEADING_TEXT`

应该框：

- `hdg 063°`
- `heading 100°`
- `063°`，如果它明确是复飞 heading。

判断标准：

- 它应支持 `Q4_course_or_radial` 中的 course/heading。
- 如果航图上同一个角度出现在 profile 和复飞小表格，要优先选择复飞小表格里的证据。

不能框：

- 最终进近航向、普通 profile 角度，除非它属于复飞指令。

#### `TRACK_OR_RADIAL_TEXT`

应该框：

- `tr 284°`
- `track 284°`
- `284°`
- 没有明确 `hdg` 但表示 track/course/radial 的文字。

判断标准：

- 它通常对应 `Q4_course_or_radial` 或 holding inbound course。

不能框：

- 与复飞无关的普通航迹角度。

#### `OUTBOUND_INBOUND_MARK`

应该框：

- `outbnd`
- `inbnd`
- `outbound`
- `inbound`

判断标准：

- 它通常和 navaid radial 一起出现。
- 例如 `COE R-350 outbnd`，需要框 `COE`、`R-350`、`outbnd`。

#### `PATH_SEGMENT`

应该框：

- 复飞转弯弧线。
- 复飞路径线段。
- 表示 direct/turn 的小表格曲线。

判断标准：

- 它通常支持 `Q3_turn` 或 `Q4_course_or_radial`。
- 如果小表格中有弯曲箭头，应该框曲线或箭头主体。

不能框：

- 普通进近路径线。
- 跑道图线段。

#### `HOLDING_PATTERN` / `HOLDING_ARC`

应该框：

- holding racetrack。
- holding arc。
- hold 的转弯图形。

判断标准：

- 它通常支持 `Q5_hold_params`。
- 如果有 `hold`，要确认 holding fix、inbound course、time/distance、turn direction 是否都能对应。

#### `HOLDING_TIME_TEXT`

应该框：

- `1 min`
- `One Minute Holding Pattern`
- holding 时间参数。

#### `DME_DISTANCE_TEXT`

应该框：

- `20.5 DME`
- `11.3 DME`
- `4 NM`
- `5 NM`

判断标准：

- 只有当这个距离属于复飞/holding 参数时才框。
- FAF 到 MAP 的距离、进近距离不一定是复飞字段。

### 1.4 确认字段映射是否正确

这是最关键的一步。

每个被确认的小框，必须能回答：

- 第几个航段？
- 航段类型是什么？
- 对应 PR #28 最大集合中的哪个 Q 字段？
- 这个框里的可见证据是否支持该字段的值？

PR #28 字段含义如下：

| 字段 | 人工要确认什么 |
|---|---|
| `Q_terminator` | 航段类型，例如 `CA`、`VI`、`CF`、`DF`、`HM`。通常来自 CIFP/424，不要求图上单独画框。 |
| `Q1_fix_ident` | 本航段目标 fix 或 navaid，例如 `MUDRE`、`ZEXEL`、`SWOBS`。 |
| `Q2_altitude_constraint` | 高度限制，例如不低于 `3000 ft`、爬升到 `7000 ft`。 |
| `Q3_turn` | 转弯方向或转弯证据，例如 left turn、right turn、弯曲路径。 |
| `Q4_course_or_radial` | 航向、track、course、radial，例如 `hdg 063°`、`tr 284°`、`STW R-243 inbound`。 |
| `Q5_hold_params` | holding 参数，例如 holding fix、inbound course、1 minute、4 NM、left/right turn。 |

确认 mapping 时要看右侧“字段对应”。

如果右侧显示：

`航段 2 · CF（飞向指定点）`

`字段：Q1_fix_ident · 定位点 / 导航台`

`应看到：MUDRE`

那么你必须确认：

- 当前框中确实能看到 `MUDRE`。
- 这个 `MUDRE` 是复飞相关，不是别的进近段无关 fix。
- 它属于航段 2，而不是航段 1 或航段 3。
- 如果都对，点击“确认对应”。

如果当前框是 `3000`，右侧却说对应 `Q1_fix_ident = MUDRE`，这就是错映射，不能确认。

---

### 1.5 确认最终 JSON 是否完整

最终保存前要看右侧“PR #28 JSON 对齐/证据覆盖”。

重点看：

- `present_total`：本图中需要图上证据的 present 字段总数。
- `present_covered`：人工已确认覆盖的 present 字段数。
- `present_evidence_coverage`：present 字段证据覆盖率。
- missing 列表：还缺哪些字段。

保存前理想状态：

- 待确认候选尽量为 0。
- 明显错误框已删除、拒绝或标不确定。
- `present_covered` 尽量等于 `present_total`。
- missing 里没有你能在图上找到但尚未确认的字段。
- 如果某字段图上确实不可见，需要标不确定或写备注，不要硬确认。

## 2. 标注网页怎么操作

### 2.1 进入网页

正式标注网页：

`http://主机IP:8787/formal/`

本机访问：

`http://127.0.0.1:8787/formal/`

练习网页：

`http://主机IP:8787/practice/`

练习网页只用于熟悉流程，不进入正式 300 张结果。

---

### 2.2 填写标注人

操作：

1. 在右上角“标注人”输入自己的固定编号。
2. 不要中途频繁更换编号。
3. 如果刷新网页，系统通常会记住上次填写的编号。

推荐格式：

- `A01`
- `A02`
- `B01`
- `LXL`
- `ZhangSan`

不推荐：

- `1`
- `test`
- 空白
- 多个人共用同一个名字

---

### 2.3 领取航图

操作：

1. 看左侧航图列表。
2. 找到显示“未领取”的航图。
3. 点击该卡片上的“领取”按钮。
4. 状态变成“我已领取”后开始标注。

状态含义：

| 状态 | 含义 | 能否操作 |
|---|---|---|
| 未领取 | 没人做 | 可以领取 |
| 我已领取 | 当前标注人已领取 | 可以标注、保存 |
| 我已提交 | 当前标注人保存过 | 可以继续修改后再保存 |
| 已被 xxx 领取 | 别人正在做 | 不要操作 |

注意：

- 打开航图不等于领取。
- 保存正式结果前必须领取。
- 如果你发现自己领取错了图，先不要保存，告诉负责人处理 `claims.json`。

---

### 2.4 打开航图

点击左侧航图卡片主体可以打开航图。

打开后中间会显示航图和预标注框。

如果看不清：

- 使用中间“航图缩放”的 `+`、`-`。
- 或按住 `Ctrl`，滚动鼠标滚轮。
- 缩放只影响当前区域，不影响其他区域。

---

### 2.5 快速确认已有候选

如果预标注框整体看起来合理，可以先使用“快速确认已有候选”。

适合使用的情况：

- 大多数小框都框在复飞小表格或复飞相关区域。
- 文字框和符号框没有明显跑偏。
- 右侧字段对应大体正确。

不适合使用的情况：

- 小框大量框到普通进近 profile。
- 框选位置明显错位。
- 很多重复框或无关框。
- 你还没有看清楚图。

操作：

1. 看中间图，粗略确认预标注质量。
2. 点击右侧或简化操作区的“快速确认已有候选”。
3. 如果发现误点，立即点击“撤销快速确认”。
4. 再逐个处理剩余 missing 或明显错误框。

重要提醒：

- 快速确认是为了减少点击量，不代表可以不检查。
- 如果框错了但你快速确认了，最终 JSON 可能仍然匹配 canonical，但证据框是错的。
- 所以快速确认后仍要检查明显错误区域。

---

### 2.6 逐个确认框

操作：

1. 点击中间航图上的一个框。
2. 右侧“当前框”会显示该框类型和说明。
3. 看“字段对应”中列出的候选映射。
4. 如果框内证据确实支持该字段，点击“确认对应”。
5. 如果多个字段都由同一个框支持，可以逐个确认。
6. 如果这个框完全不对，选择“不属于此框”或删除/标不确定。

判断方法：

- 框里看到的值，必须和右侧“应看到”一致。
- 航段编号必须一致。
- 航段类型要合理。
- 字段类型要合理。

示例：

框里是 `3000`。

可以确认：

- `Q2_altitude_constraint = AT_OR_ABOVE 3000 ft`

不能确认：

- `Q1_fix_ident = MUDRE`
- `Q4_course_or_radial = STW R-243`

---

### 2.7 处理 missing 字段

如果右侧显示 missing，说明某个 `present` 字段还没有人工证据。

操作：

1. 在“需要优先补证据的字段”里看缺什么。
2. 点击该字段旁边的“去候选字段处理”。
3. 在航图中找对应证据。
4. 如果图上已有正确框，先点击那个框。
5. 在“候选目标字段”中找到对应航段和字段。
6. 点击“挂到当前框”。
7. 回到“字段对应”，点击“确认对应”。

如果图上没有框：

1. 在上方下拉栏选择合适框类型。
2. 点击“框选新增”。
3. 在航图上贴着证据画新框。
4. 选中新框。
5. 在候选字段里挂接对应字段。
6. 确认对应。

如果图上真的找不到：

- 不要硬确认。
- 标记为不确定。
- 在备注写原因，例如“图上未找到该 radial 文字，只在 424 中存在”。

---

### 2.8 新增框怎么画

新增框原则：

- 宁可小而准，不要大而乱。
- 一个小框尽量只框一个文字或符号。
- 如果一个复飞步骤格子里有多个元素，应分开框。

操作：

1. 在航图上方下拉栏选择类型。
2. 点击“框选新增”。
3. 鼠标拖拽画框。
4. 画完后点击新框。
5. 在候选字段里挂接字段。
6. 确认对应。

常见类型选择：

| 看到的内容 | 选择类型 |
|---|---|
| `3000`、`7000` | `ALTITUDE_TEXT` |
| 向上箭头 | `CLIMB_ARROW` |
| `MUDRE`、`ZEXEL` | `FIX_TEXT` |
| fix 菱形/星形符号 | `FIX_SYMBOL` |
| `STW`、`COE`、`BOS` | `NAVAID_TEXT` |
| `R-243`、`R-350` | `RADIAL_TEXT` |
| `hdg 063°` | `HEADING_TEXT` |
| `tr 284°` | `TRACK_OR_RADIAL_TEXT` |
| `inbound`、`outbnd` | `OUTBOUND_INBOUND_MARK` |
| holding 图形 | `HOLDING_PATTERN` 或 `HOLDING_ARC` |
| `1 min` | `HOLDING_TIME_TEXT` |
| `20.5 DME`、`4 NM` | `DME_DISTANCE_TEXT` |

---

### 2.9 删除或拒绝错误框

如果框完全无关：

- 可以删除当前框。

如果框位置有点对，但字段映射错了：

- 不要删框。
- 移除或拒绝错误 mapping。
- 再挂接正确字段。

如果框有用但不确定：

- 标记“不确定”。
- 写备注。

不要这样做：

- 不要为了让覆盖率变高而确认错字段。
- 不要把框到无关内容的框确认成正确。
- 不要随便删除可能有用的证据框。

---

## 3. 保存后系统如何生成 JSON

保存时系统会做以下事情。

### 3.1 收集人工 accepted mapping

系统只看人工确认过的 mapping：

`human_decision === "accepted"`

未确认的 pending 不进入最终 present 字段。

被拒绝的 rejected 不进入最终 JSON。

### 3.2 生成 `annotation_pr28_json`

系统生成和 PR #28 canonical 完全同构的 JSON。

结构包括：

- `chart_id`
- `procedure`
- `missed_approach.leg_count`
- `missed_approach.legs[]`
- 每个 leg 的：
- `Q_terminator`
- `Q1_fix_ident`
- `Q2_altitude_constraint`
- `Q3_turn`
- `Q4_course_or_radial`
- `Q5_hold_params`

### 3.3 自动保留不用画框的字段

以下字段通常直接保留 424 canonical 状态：

- `Q_terminator`
- `not_applicable`
- `not_observable`
- `unknown`

原因：

- 它们不一定有图上可见框。
- 人工主要负责 `present` 字段的图上证据。

### 3.4 present 字段由人工证据决定

对于 `present` 字段：

- 未人工确认前是 `unknown`。
- 人工确认后写入对应 canonical answer。

这样可以确保：

- 人工没确认的字段不会被误当成完成。
- 人工确认完整后，JSON 格式与 424 canonical 一致。

---

## 4. 系统如何和 424 JSON 对比

系统会把两个 JSON 展平成逐字段列表。

例如：

- `leg_count`
- `leg1.Q_terminator`
- `leg1.Q1_fix_ident`
- `leg1.Q2_altitude_constraint`
- `leg1.Q3_turn`
- `leg1.Q4_course_or_radial`
- `leg1.Q5_hold_params`
- `leg2.Q_terminator`
- ...

然后比较：

- 字段是否存在。
- `status` 是否一致。
- `value` 是否一致。

保存文件中会包含：

- `annotation_pr28_json`
- `canonical_gt_file`
- `pr28_comparison_summary`

`pr28_comparison_summary` 中常见指标：

| 指标 | 含义 |
|---|---|
| `total` | PR #28 展开后的总字段数 |
| `matched` | 和 424 canonical 完全一致的字段数 |
| `covered` | 非 unknown 字段数 |
| `present_total` | 需要图上证据的 present 字段数 |
| `present_covered` | 已由人工 accepted 覆盖的 present 字段数 |
| `present_matched` | present 字段中和 canonical 一致的字段数 |
| `present_evidence_coverage` | present 字段证据覆盖率 |
| `full_alignment_rate` | 全字段对齐率 |

重要说明：

这些指标是“人工证据覆盖/对齐指标”，不是独立 OCR 或 LLM 抽取正确率。

原因：

- 候选字段来自 CIFP/424 canonical target。
- 人工是在确认图上证据是否支持 canonical 字段。
- 真正 OCR/LLM 实验应使用独立 OCR/模型输出 JSON，再和 canonical JSON 比。

---

## 5. 什么情况下可以保存

可以保存的条件：

- 当前图已经由你领取。
- 大框基本正确。
- 明显错误小框已处理。
- 需要图上证据的 present 字段尽量都已确认。
- 右侧 missing 列表没有你能找到但没处理的字段。
- 不确定内容已经写备注。

保存后文件位置：

- 当前标注人的最新结果：`datasets\formal300\annotations\by_annotator\{标注人}\{chart_id}.json`
- 每次提交快照：`datasets\formal300\annotations\submissions\{chart_id}\*.json`
- 领取记录：`datasets\formal300\annotations\claims.json`

---

## 6. 什么情况下不能当最终完成

以下情况不能当最终完成：

- `present_covered < present_total`，并且 missing 字段能在图上找到。
- 大量框明显跑偏。
- 小框框到了普通进近 profile，而不是复飞 detail。
- 航段编号挂错。
- 字段类型挂错。
- 同一个证据被错误挂到多个不相关字段。
- 人工只是快速确认，没有检查明显错误。
- 保存文件中有大量 pending，但没有备注说明。

## 7. 常见错误示例

### 7.1 把普通 profile 高度当成复飞高度

错误：

- 图上 profile 中有 `2400`。
- 复飞小表格中也有 `2400`。
- 人工确认了 profile 中的 `2400`。

正确：

- 优先确认复飞小表格里的 `2400`。
- 如果 profile 中的 `2400` 不是复飞步骤证据，不应确认。

### 7.2 把 heading 当 fix

错误：

- 框里是 `hdg 063°`。
- 却确认到 `Q1_fix_ident = MUDRE`。

正确：

- `hdg 063°` 应对应 `Q4_course_or_radial`。
- `MUDRE` 应由 `FIX_TEXT` 或 `FIX_SYMBOL` 支持。

### 7.3 把上方大框拆得太细

错误：

- 把上方 `MISSED APPROACH` 文字逐词框选。

正确：

- 上方文字用一个大框覆盖即可。
- 细致小框主要针对下方复飞 detail 区域和平面图中必要符号。

### 7.4 忘记确认 outbound/inbound

错误：

- `COE R-350 inbound` 只确认了 `COE` 和 `R-350`。
- 漏掉 `inbound`。

正确：

- 如果 PR #28 字段包含 direction，应确认 `inbound/outbound/outbnd/inbnd` 证据。

### 7.5 holding 只确认 fix，没确认 holding 参数

错误：

- 只框了 holding fix。
- 没处理 inbound course、time、distance、turn direction。

正确：

- `Q5_hold_params` 需要尽量确认 holding 图形和相关参数。
- 如果图上只可见一部分，标不确定并备注。

## 8. 最终检查清单

保存前逐项检查：

- 我是否填写了固定标注人？
- 这张图是否显示“我已领取”？
- 上方复飞文字大框是否覆盖完整？
- 平面图复飞相关区域是否覆盖合理？
- 下方复飞 detail 总框是否框到真正复飞小表格？
- 高度、箭头、fix、navaid、radial、heading/track、holding、DME 是否尽量逐个小框确认？
- 每个 accepted mapping 是否能说清第几个航段、什么航段类型、哪个 Q 字段？
- missing 字段是否已处理？
- 不确定字段是否写了备注？
- 是否避免把人工证据覆盖率当成独立模型正确率？

如果以上都完成，可以保存人工校准。

---

## 9. 给标注人的一句话版本

你要做的不是“看图写答案”，而是“确认图上的框能不能证明 424/PR #28 JSON 里的某个航段字段”。每次确认都要问自己三件事：

1. 这个框里的东西对不对？
2. 它属于第几个复飞航段？
3. 它对应 PR #28 最大集合里的哪个 Q 字段？

这三件事都能回答清楚，才能点确认。
