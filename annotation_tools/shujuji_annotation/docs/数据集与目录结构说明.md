# 数据集与目录结构说明

## 数据集来源

- 正式集严格以 2604 cycle 为主：FAA CIFP 原始编码来自 `..\..\data\v2604_100\cifp\FAACIFP18`。
- 航图优先使用本机已有 PDF/图片；如果后续缺 PDF，构建脚本会按候选池中的 FAA 官方 `pdf_url` 下载到 `source_cache\faa_d_tpp_2604`。
- PR #28 目标格式统一为 `missed_approach_leg_v1_pr28`：每个复飞航段包含 `Q_terminator`、`Q1_fix_ident`、`Q2_altitude_constraint`、`Q3_turn`、`Q4_course_or_radial`、`Q5_hold_params`。

## 正式 300 张选择规则

- 先保留第一版已经形成的 100 张 2604 样本，保证与前期实验可追溯。
- 再从候选池中补 200 张 RNAV 复飞相关航图，满足 issue 中“由 100 扩展到 300，并增加 RNAV 覆盖”的要求。
- 选择时优先本地已有 PDF、优先复飞航段数更多的样本，并使用机场上限控制分布；为了凑足 200 张 RNAV 扩展样本，机场上限使用 3。
- 正式集随机种子固定为 `2604`，切分为 `development=200`、`evaluation=75`、`probe=25`，保证可复现。

## 目录结构

- `datasets\practice10`：10 张练习图，保存结果不进入正式统计。
- `datasets\formal300`：300 张正式图，是最终人工校准数据集。
- `images`：网页加载的航图图片。
- `pdfs`：正式集对应 PDF 备份。
- `prelabels`：自动预标注/候选框。
- `targets\canonical_proxy_gt`：每张图从 CIFP/424 转换来的 PR #28 canonical JSON。
- `targets\canonical_targets.json`：网页右侧候选字段和航段字段映射来源。
- `annotations\claims.json`：正式集多人领取状态，防止重复标注。
- `annotations\by_annotator\<标注人>`：每个标注人当前最新版。
- `annotations\submissions\<chart_id>`：每次保存的时间戳快照。

## 正式集小框预标注

- 正式集 `prelabels` 已补充为 `v0.22-formal300-icon-aligned-prelabels`。
- 每张图保留 3 个大框：上方复飞文字、平面图、下方复飞细节区域。
- 每张图额外生成下方细节小框：高度、爬升箭头、fix/navaid、radial/track、转弯路径、holding、DME/距离等。
- 10 张与练习集重合的航图优先复制已校准的小框；其余航图先用 PDF 文字坐标定位下方复飞细节/图标区域，再用图像连通域检测爬升箭头、fix symbol、holding/path 图形候选。
- 小框是预标注候选，不是最终真值；人工仍需要检查、移动、删除或补框。
- 旧模板生成脚本：`scripts\generate_formal_small_prelabels.py`。
- 当前推荐生成脚本：`scripts\generate_formal_icon_aligned_prelabels.py`。
- 当前生成报告：`datasets\formal300\reports\formal300_icon_aligned_prelabels_report.json`。

## 多人协同原则

- 多人不是同时标同一张图，而是每个人领取不同航图。
- 正式入口必须先填写标注人；点击未领取航图后，该图会被锁定到该标注人。
- 其他人不能打开或保存已被领取的航图，避免重复和覆盖。
- 如果误领，负责人检查并必要时修改 `annotations\claims.json`。
