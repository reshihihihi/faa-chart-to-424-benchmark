# Shujuji Annotation Platform

这是复飞航图标注平台的 Node.js 服务端和浏览器前端。它不依赖数据库，运行时通过 JSON 文件保存领取、暂存和正式提交结果。

## 启动

```powershell
node server.js
```

可选环境变量：

- `PORT`：服务端口，默认 `8787`。
- `PUBLIC_BASE_URL`：公网部署后的域名，仅用于日志提示。
- `SHUJUJI_ACCESS_TOKEN`：公网访问口令。设置后所有 `/api/*` 和图片接口都需要 token。
- `SHUJUJI_ADMIN_TOKEN`：后台管理口令，用于 `/admin/` 进度总览和导出；也可作为专家复核口令使用。
- `SHUJUJI_EXPERT_TOKEN`：专家复核口令。未单独设置时，专家页可使用后台管理口令。
- `SHUJUJI_DATA_ROOT`：人工标注结果的持久化根目录。未设置时写回 `../datasets/*/annotations/`。

## 入口

- `/practice/`：10 张练习集。
- `/formal/`：300 张正式集。
- `/expert/`：专家复核队列。普通标注人提交专家复核后，专家在这里领取，承接原草稿并提交最终结果。
- `/admin/`：后台进度、逐图总览、展示页入口和导出。
- `/healthz`：健康检查，不返回服务器绝对路径。

公网正式入口示例：

```text
https://你的域名/formal/?token=你的口令
```

专家复核入口示例：

```text
https://你的域名/expert/?token=专家或后台口令&expert=E01
```

## 正式标注闭环

1. 普通标注人进入 `/formal/`，填写或通过链接带入 `annotator=A06`，系统自动领取下一张未分配航图。
2. 可以暂存、换一张、提交，或在无法判断时点击“提交专家复核”。提交复核前会先保存当前草稿，因此已框选证据和已完成字段不会丢。
3. 进入专家复核的航图会从普通队列移出，在 `/admin/` 中显示为“待专家复核”或“专家复核中”。
4. 专家进入 `/expert/`，填写或通过链接带入 `expert=E01`，系统领取待复核航图，并加载普通标注人留下的草稿。
5. 专家可以继续修改证据和字段结论，提交后写入正式结果；后台会保留原标注人、复核人、退回原因和提交快照。

## 设计约束

- 航图、预标注和 canonical targets 是只读实验素材。
- 人工领取、暂存、正式提交是运行时数据，公网部署时应写入持久化磁盘。
- API 响应不得返回服务器本机路径、提交文件路径或快照文件路径。
