# Pre-Freeze Alignment Contract

Status: partially frozen on 2026-04-27.

This document records the experiment logic that is frozen before the full formal evaluation freeze. It is intended to prevent method drift while the remaining data, target, scorer, model, and prompt assets are still being prepared.

## Current Freeze Scope

Frozen now:

- canonical JSON schema contract v1;
- B1 method boundary and allowed/forbidden inputs;
- C3 method boundary and allowed/forbidden inputs;
- strict raw JSON output policy;
- parser repair policy: no code-fence stripping, no first-object extraction, no semantic repair;
- assistant prefill JSON output control with `{`;
- pilot10 external samples are pilot-only and excluded from formal evaluation;
- B1/C3 run artifact layout.

Not frozen yet:

- model/provider/max token settings;
- formal B1/C3 prompt text;
- OCR artifact policy for formal B1;
- formal300 sample manifest and split;
- formal canonical targets;
- `field_targets.jsonl`, `evidence_provenance.jsonl`, and `challenge_tags.jsonl`;
- scorer and statistical reporting implementation;
- final rerun policy;
- non-B1/C3 method prompts and runners.

## Canonical Output Contract

All extraction methods, except direct verification tasks, must ultimately produce canonical JSON that validates against:

```text
schemas/missed_approach_leg.schema.json
sha256: 7ccb2cb9dcc73e67167d7ae5a8874e73dc201f56ad243615009db620494482d9
```

C3 questionnaire JSON is an intermediate artifact, not the final prediction. It must be deterministically converted to the canonical JSON schema before validation and scoring.

## Frozen B1 Boundary

```text
B1 = full chart -> full-chart OCR text -> LLM -> canonical JSON
```

Allowed B1 inputs:

- chart metadata: `chart_id`, `airport`, `approach_ident`, `chart_name`;
- full-chart OCR text generated by the registered OCR process;
- the canonical output contract.

Forbidden B1 inputs:

- chart image pixels;
- OCR bbox or coordinates;
- ROI, prelabels, or human annotation boxes;
- automatic field candidates;
- field-to-leg candidates;
- gold MA prose;
- gold observable evidence;
- canonical target or answer key;
- `field_targets.jsonl`;
- `evidence_provenance.jsonl`;
- `challenge_tags.jsonl`;
- scorer outputs;
- CIFP or ARINC 424 records;
- historical model outputs for the same chart.

## Strict Raw JSON Contract

B1 and C3 raw model outputs must be bare JSON objects.

Frozen rules:

- first non-whitespace character is `{`;
- last non-whitespace character is `}`;
- no markdown code fence;
- no natural-language prefix or suffix;
- no parser repair beyond whitespace trim and JSON parsing;
- no semantic repair;
- code fence is a format violation in strict mode.

Call-level output control is frozen as:

```text
assistant_prefill_json: true
assistant_prefill_value: "{"
```

This is a formatting control, not a semantic hint.

## Pilot Evidence

The strict raw JSON + assistant prefill policy was validated on the pilot10 external set:

```text
run_id: pilot10_exp1_b1_c3_strict_json_prefill_20260427_r1
sample role: pilot-only / external / excluded from formal evaluation
```

Observed pilot results:

| Method | strict JSON | schema valid | parser repair count | score |
|---|---:|---:|---:|---:|
| B1 | 10/10 | 10/10 | 0 | 94/220 |
| C3 | 10/10 | 10/10 | 0 | 66/220 |

Pilot scores are evidence that the chain runs. They are not formal evaluation results and must not be used to tune on the formal evaluation split.

## Run Artifact Layout

Every B1/C3 run should preserve:

```text
raw_text/
raw_responses/
questionnaire_json/    # C3 only
canonical_json/
validation/
scores/
run_manifest.json
summary_report.json
logs/
```

Every formal-style run must preserve failures rather than deleting or replacing them.

## Red Lines

Do not:

- modify the schema after seeing pilot/eval outputs to make model output pass;
- give B1 field candidates, ROI, target, or image pixels;
- give C3 OCR text, field candidates, ROI, or target;
- treat C3 questionnaire JSON as final prediction;
- strip markdown code fences in strict formal-style runs;
- use formal evaluation samples for prompt or parser tuning;
- mix pilot results into formal evaluation results;
- rerun low-score, parse-failure, or schema-failure samples without a frozen rerun policy and a new run id.
