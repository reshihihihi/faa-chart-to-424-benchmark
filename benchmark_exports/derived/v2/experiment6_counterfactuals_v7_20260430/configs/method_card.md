# Experiment Group 6 Method Card

## Purpose

Experiment Group 6 tests whether a method can verify consistency between an FAA
instrument procedure chart and a candidate 424-like missed-approach record.

This is a verification task, not a canonical JSON extraction task.

## Task

```text
Input:  full chart image + candidate 424-like missed-approach record
Output: audit decision JSON
```

The verifier must decide whether the candidate record is consistent with the
chart. If inconsistent, it must identify the wrong field paths.

## Relation To Other Experiment Groups

- Group 1 produces full-chart canonical extraction predictions.
- Group 2 provides evidence provenance for analysis, not model input.
- Group 3 provides challenge tags for analysis, not model input.
- Group 5 oracle evidence may support QC and optional oracle comparison, but it
  must not be leaked into direct verifier inputs.

## Candidate Construction

Positive candidates are projected from formal canonical targets.

Negative candidates are generated by minimal, plausible semantic mutations of a
positive candidate. The main set should prefer single-field mutations so that
error localization is well-defined.

## Allowed Inputs

For direct chart-aware verification:

- Full chart image.
- Candidate 424-like missed-approach record.
- Non-answer chart metadata needed to load or display the chart, such as
  `chart_id`, `sample_id`, and image path.

For text-only verification:

- Frozen OCR-1 full-chart text.
- Candidate 424-like missed-approach record.
- Non-answer chart metadata.

For candidate-only baseline:

- Candidate 424-like missed-approach record only.

## Forbidden Inputs

The verifier input must not include:

- canonical target JSON;
- `consistent` labels;
- `error_fields`;
- `counterfactual_type`;
- scorer output;
- evidence provenance;
- challenge tags;
- raw CIFP records;
- outputs from other methods, except in the explicit extract-then-compare route;
- any field that directly states whether the candidate is positive or negative.

## Output

The model output must be bare JSON that conforms to
`configs/audit_decision_schema.json`.

Markdown code fences, explanations outside JSON, and wrapper objects are not
valid formal outputs.

## Method Variants

The frozen Group 6 variant names are:

| ID | Method | Input | Purpose |
|---|---|---|---|
| V0 | candidate-only baseline | candidate record only | Detect counterfactual artifacts |
| V1 | text-only verifier | OCR/text evidence + candidate | Measure text shortcut |
| V2 | direct VLM verifier | full chart image + candidate | Main chart-aware verification |
| V3 | extract-then-compare | frozen Group 1 extraction + symbolic comparer | Test canonical schema as audit intermediate |
| V4 | SFT verifier, optional | full chart image + candidate | Test trained verifier |

Earlier pre-freeze files may contain the old names `V3_direct_vlm` or
`metadata-only`; those are legacy pilot labels. Formal Group 6 reports must use
the table above.

## Main Metrics

- false negative rate;
- binary consistency accuracy;
- false positive rate;
- error localization accuracy;
- field mismatch recall;
- by-counterfactual-type accuracy;
- candidate-only artifact score.

False negative rate is primary because an incorrect 424-like record being
accepted as consistent is the most dangerous verification failure.
