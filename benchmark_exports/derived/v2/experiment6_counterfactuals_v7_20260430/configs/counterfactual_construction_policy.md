# Experiment 6 Counterfactual Construction Policy

Status: pre-freeze candidate.

## Goal

Construct verification cases that test whether a method can detect plausible
424-like missed-approach record errors from chart evidence.

## Positive Cases

Positive cases are generated by projecting a frozen canonical target into the
candidate 424-like schema.

Rules:

- `consistent = true`
- `error_fields = []`
- `counterfactual_type = "positive"`
- No target JSON is included in verifier inputs.

## Negative Cases

Negative cases are generated from positive candidates by minimal semantic
mutation.

Main-set rules:

1. Prefer one semantic mutation per negative case.
2. The mutated value must be plausible.
3. Do not use obviously invalid values such as `INVALID`, `XXXXX`, or
   `999999 ft`.
4. Every negative case must have explicit `error_fields`.
5. The candidate-only baseline must remain low; otherwise the negative cases
   contain artifacts.
6. High-risk counterfactuals require manual review before formal freeze.

## Required Counterfactual Types

The formal set should cover:

- fix substitution;
- altitude perturbation;
- turn direction flip;
- course / radial error;
- holding parameter error;
- implicit hold time omission;
- path terminator substitution;
- CA omission;
- CA to DF sequence error;
- text-only trap;
- 424-derived trap.

The automatic builder may produce a subset if the canonical target does not
contain the required source field. Missing types must be listed in the QC
report and handled manually or by a later builder version.

## Automatic Builder Policy

The automatic pre-freeze builder may generate:

- `positive`
- `fix_substitution`
- `altitude_perturbation`
- `turn_direction_flip`
- `course_radial_error`
- `holding_parameter_error`
- `implicit_hold_time_omission`
- `path_terminator_substitution`
- `ca_omission`
- `text_only_trap`
- `424_derived_trap`
- `ca_to_df_sequence_error`

It should skip a mutation when the target does not provide enough information
to create a plausible single-field change.

Additional pre-freeze v3 rules:

- `text_only_trap` keeps text-like fix and altitude fields stable while
  perturbing a graphical or derived course/radial/holding parameter.
- `424_derived_trap` preserves visible fix/altitude values while perturbing a
  structurally plausible path terminator code.
- `ca_omission` omits a required climb-to-altitude leg and is labeled as a
  sequence-level error with `missed_approach.legs.sequence`.
- `ca_to_df_sequence_error` omits an initial CA climb leg and expresses the
  following to-fix leg as a DF-style direct-to-fix segment. This is a
  sequence-level error and should be scored with
  `missed_approach.legs.sequence`.

Additional pre-freeze v5 rules:

- `fix_substitution` must replace a linked missed-approach target fix with
  another fix from the same chart/procedure raw CIFP transition pool. It must
  not use a global external fix pool, and it should avoid replacing a target
  fix with another fix already used by the missed-approach target because that
  creates candidate-only duplicate-fix artifacts.
- `altitude_perturbation` must replace an altitude with another canonical chart
  altitude from the same candidate. If the candidate has only one unique
  altitude, the builder must skip this mutation rather than inventing a +100 ft
  value.

Additional pre-freeze v7 rule:

- When several same-chart/procedure fix replacements are available, prefer a
  5-letter waypoint-style ident over a 3-letter navaid and prefer both over
  localizer-style `I...` identifiers. This reduces unnatural candidate records
  while keeping the replacement within the same procedure evidence pool.

## Formal Freeze Requirements

Before formal freeze, record:

- builder script path and hash;
- canonical schema path and hash;
- target manifest path and hash;
- counterfactual type counts;
- no-leakage report;
- candidate-only baseline score;
- human review acceptance rate for sampled cases.
